# Проект ОПД · Завод роботов

Рабочая основа турнирного проекта по спецификации v1: HTTP API арены,
заменяемая стратегия, память отдельных прогонов, собственный симулятор и веб-панель.
Python 3.9+, внешние зависимости не требуются.

## Запуск

Из корня проекта:

```sh
python3 -m factory.server
```

Открыть http://127.0.0.1:4001. В другом терминале запустить демонстрационную смену:

```sh
python3 -m scripts.demo --url http://127.0.0.1:4001 --seed 1 --delay 0.03
```

В панели появятся прогон, баланс, станки, покупатели, склад, последние команды
и результаты их выполнения. История баланса сохраняется на сервере по тактам
до его перезапуска: график доступен и после обновления страницы. Доступны светлая
и тёмная темы, фильтры предметов и событий, пауза обновления и экспорт снимка
прогона в JSON (включает до 100 последних событий). Кнопка «Запустить смену»
показывает команду для локального запуска в терминале. Состояние завода
показывает последний снимок арены до команд текущего события; итоговая прибыль
берётся из finish. Интерфейс обновляется каждые 1,5 секунды; в неактивной вкладке опрос приостанавливается.

Быстрый прогон без сети и интерфейса:

```sh
python3 -m scripts.demo --seed 1
python3 -m unittest discover -s tests -v
```

Остановка сервера — Ctrl+C. Состояние находится в памяти и сбрасывается при перезапуске.

## Структура

| Путь | Ответственность |
| --- | --- |
| `factory/server.py` | HTTP, JSON, маршруты арены, CORS, токен, статические файлы |
| `factory/runs.py` | Прогоны по runId, блокировки, ответы по seq, журнал и снимки |
| `factory/strategy.py` | Контракт Strategy и начальный алгоритм |
| `factory/domain.py` | Совпадение шаблонов, выбор входов, наследование свойств |
| `factory/config.py` | Открытая конфигурация v1 для собственных тестов |
| `factory/simulator.py` | Поставки, станки, склад, скрытый рынок и подсчёт прибыли |
| `scripts/demo.py` | Прогон через HTTP или напрямую |
| `web/` | Панель наблюдения без сборки и библиотек |
| `tests/` | Проверки HTTP, изоляции, повторов и локальных миров |
| `docs/architecture.md` | Архитектура, ограничения, дальнейшие задачи |

## API

- `GET /v1/health` → `{"status":"ok"}`.
- `GET /v1/info` → имя, версия, project, specVersion.
- `POST /v1/runs/{runId}/start` → `{"ok":true}`.
- `POST /v1/runs/{runId}/event` → `{"commands":[...]}`.
- `POST /v1/runs/{runId}/finish` → `{"ok":true}`.
- `GET /api/runs` → список прогонов для интерфейса.
- `GET /api/runs/{runId}` → последний снимок, результат, до 100 записей журнала.

Ошибки возвращаются в формате `{"error":{"code":"...","message":"..."}}`.
Поддерживается `X-Arena-Spec: v1`. Если передан `X-Arena-Seq`, он должен совпадать
с seq JSON-события. Повторный seq возвращает сохранённый ответ без повторного
вызова стратегии. Запросы одного прогона сериализованы; разные runId изолированы.
Кэш ответов хранится до остановки сервера, включая завершённые прогоны.

Для браузерной песочницы реализованы OPTIONS, CORS и Private Network Access.
Для зачётного раунда потребуется публичный HTTPS-адрес/туннель и проверка
официальной кнопкой «Проверить API». В этой версии внешний адрес не настроен.

Опционально задайте переменную окружения `ARENA_TOKEN`: все API-маршруты,
включая health и данные панели, потребуют `Authorization: Bearer ...`.
Тот же токен нужно указать в кабинете арены и в поле панели. Для demo переменная
должна быть задана и в терминале клиента. Токен в браузере не сохраняется.
Для прослушивания внешних интерфейсов: `python3 -m factory.server --host 0.0.0.0`.

## Начальная стратегия

Алгоритм поддерживает небольшие запасы листов и элементов управления, запускает
производство по доступным операциям, чередует цвета и наличие ручек, предлагает
готовые роботы свободным покупателям с minPrice=1. При отказе робот может быть
предложен следующему доступному покупателю. Учёт свободных мест консервативен:
место после offer не считается освобождённым, пока продажа не подтверждена.
Баланс не ограничивает закупки. Есть начальные ограничения запуска перед концом
смены, но оптимизация последних тактов ещё не реализована.

Это алгоритм для проверки системы: он не изучает предпочтения, не оптимизирует
цену и не должен рассматриваться как готовая турнирная стратегия.

Симулятор реализует основные правила v1 и воспроизводится по seed. Его генератор
миров собственный: результаты не сопоставимы напрямую с seed и эталонными цифрами
официальной арены. Арена остаётся источником окончательной проверки.
