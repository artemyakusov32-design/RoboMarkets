# RoboMarkets · Завод роботов

RoboMarkets реализует HTTP API арены по спецификации v1. В проекте есть локальный
симулятор, веб-панель и одна основная стратегия **Learning v1** с весами CMA-ES.
Для сервера, панели и локальных проверок достаточно Python 3.9+. Дополнительные
зависимости нужны только для обучения весов.

## Быстрый запуск

Из корня проекта:

```sh
python3 -m factory.server
```

Открыть http://127.0.0.1:4001 и нажать **«Запустить смену»**. Выбрать номер локального
мира (seed) и длительность, затем нажать **«Начать тестовую смену»**. Прогон появится
в панели автоматически. На сервере одновременно запускается одна тестовая смена.

Панель показывает прибыль, продажи, станки, склад, покупателей и журнал решений.
Есть фильтры предметов и событий, светлая/тёмная темы, пауза обновления и экспорт
снимка в JSON. Пауза останавливает обновление панели, производство продолжается.
История баланса сохраняется по тактам на сервере до его перезапуска.

Для обычного запуска достаточно файлов из репозитория. Сервер и локальные прогоны
сразу используют 27 обученных весов из [`factory/planning/policy.py`](factory/planning/policy.py).

## Проверка через терминал

Быстрая смена без сервера:

```sh
python3 -m scripts.demo --seed 1
```

Прогон через настоящее HTTP API с отображением в панели:

```sh
python3 -m scripts.demo --url http://127.0.0.1:4001 --seed 1 --delay 0.03
```

Проверка основной стратегии на 20 локальных мирах и регрессионные тесты:

```sh
python3 -m scripts.check_worlds --seeds 20
python3 -m unittest discover -s tests -v
```

`check_worlds` выводит прибыль каждого мира, среднюю прибыль и максимальное
время обработки события. При недопустимых командах скрипт завершается с кодом 1.

## Результаты на локальном симуляторе

В каждой строке сравниваются одинаковые миры и один набор весов. Меняется логика
продажи и планирования. Прибыль и отказы указаны в среднем за смену.

| Горизонт и диапазон seed | Прибыль до | Прибыль после | Прирост | Отказы до и после |
| --- | ---: | ---: | ---: | ---: |
| 600 тактов, 86000–86031 | 6 704,56 | 8 978,29 | +33,91% | 95,81 → 2,19 |
| 1000 тактов, 85000–85039 | 10 580,35 | 14 768,84 | +39,59% | 171,65 → 2,33 |

На 1000 тактах один низкий порог дал 14 587,18. Планирование под покупателей
добавило 1,25% к этой прибыли. В новой версии не было недопустимых команд и
таймаутов в этих прогонах.

Текущую стратегию можно проверить на тех же диапазонах.

```sh
python3 -m scripts.check_worlds --world-seed 86000 --seeds 32 --horizon 600
python3 -m scripts.check_worlds --world-seed 85000 --seeds 40 --horizon 1000
```

### Результаты обучения до обновления правил продажи

Архив и варианты весов были проверены на 100 мирах (seed 1136–1235) по 600 тактов.

| Версия Learning v1 | Прибыль | Прирост к архиву |
| --- | ---: | ---: |
| Исходный бот из `files.zip` | 5 139,00 | — |
| Интегрированный бот с ручными весами из архива | 5 278,64 | +2,72% |
| Интегрированный бот с весами CEM | 5 942,42 | +15,63% |
| Версия с весами CMA-ES до обновления порога | **6 268,15** | **+21,97%** |

Версия с весами CMA-ES дала в среднем **+1 129,14 за смену** к архиву и принесла больше
прибыли во всех 100 мирах. Общий прирост учитывает исправления при интеграции и
обучение. На интегрированном боте обученные веса дали **+18,75%** к ручным весам
и **+5,48%** к CEM. В финальном тесте CMA-ES было 0 недопустимых команд и 0 таймаутов.

## Обучение весов

CMA-ES подбирает сочетания 27 весов Learning v1 по средней прибыли в симуляторе.
Скрипт сохраняет веса и отчёт в JSON. Для подбора он использует
[pycma](https://github.com/CMA-ES/pycma).

Из корня проекта на macOS или Linux:

```sh
python3 -m venv work/training-venv
work/training-venv/bin/python -m pip install -r requirements-training.txt
work/training-venv/bin/python -m scripts.train_weights --profile standard --workers 4
```

На Windows используйте `py -3 -m venv work/training-venv` и
`work\training-venv\Scripts\python.exe` для установки зависимостей и запуска.
Параметр `--workers` задаёт число параллельных процессов. Чтобы изменить
значение, запустите обучение заново. JSON сохраняется в конце обучения.

| Профиль | Поколения × кандидаты × миров на кандидата | Уникальных тренировочных миров | Проверочных / финальных миров | Всего смен, до |
| --- | ---: | ---: | ---: | ---: |
| `quick` | 6 × 12 × 8 = 576 | 8 | 12 / 20 | 700 |
| `standard` | 20 × 24 × 24 = 11 520 | 96 | 40 / 100 | 12 560 |
| `deep` | 30 × 32 × 48 = 46 080 | 384 | 64 / 160 | 48 384 |

По умолчанию CMA-ES использует `standard`. Добавьте `--profile deep` для
длинного подбора или `--profile quick` для короткого запуска. Все смены длятся
по 600 тактов по умолчанию. Кандидаты в пределах поколения играют на одинаковых
мирах. Поколения циклически проходят блоки тренировочных миров, а проверочный и
финальный наборы используют отдельные seed. Прогон, давший текущие штатные веса,
занял **50 мин 50 с** на 8 процессах и включал 11 520 тренировочных смен
и 1 040 проверочных и финальных смен.

По умолчанию поиск начинается с текущих штатных весов. Чтобы начать с весов из
своего JSON, передайте `--initial-weights путь/к/весам.json`. Параметр
`--world-seed` задаёт начало диапазона миров. Например, `--world-seed 2000`
даст новый набор миров для следующего обучения `standard`.

Кандидат заменяет исходные веса в выходном файле, если средняя прибыль на финальных
мирах выше, все команды допустимы и события обрабатываются в пределах лимита.
В остальных случаях файл содержит исходные веса. Отчёт включает число смен,
время, диапазоны seed и прибыль. CMA-ES по умолчанию сохраняет результаты в
`work/learning-weights-cma-es.json`. Путь можно задать через `--output`.

Подключение результата и проверка на новом диапазоне:

```sh
python3 -m factory.server --weights work/learning-weights-cma-es.json
python3 -m scripts.check_worlds --weights work/learning-weights-cma-es.json --world-seed 10000 --seeds 20
```

Флаг `--weights` подключает результат к Learning v1 для арены и смен из панели.
Знания о покупателях создаются заново в каждой смене. Для справки по параметрам
обучения запустите `python3 -m scripts.train_weights --help`.

## Основная стратегия

Learning v1 адаптирована из присланного командой архива `files.zip`.
Для каждого покупателя она поддерживает гипотезы о любимом типе робота,
диапазонах Pmax и f. Продажи и отказы уточняют связанные цены с учётом шума.
Действия выбираются по линейной оценке выгоды, потребности в запасах, загрузки
склада и ценности исследования рынка. Обученной нейросети нет.

Для предложений используется порог `minPrice=10`. Покупатель платит свою цену.
Если даже верхняя оценка с учётом шума ниже порога, предложение пропускается.
При горизонте от 1000 тактов планировщик распределяет готовых роботов и уже
окрашенные заготовки по ближайшим окнам доступности покупателей. Это меняет
приоритет выпуска и оценку ожидания более выгодной сделки. Для обучения весов
с таким планированием добавьте `--horizon 1000` к команде запуска обучения.

Исправления при интеграции:

- Предложения сопоставляются с ответами по паре buyerId + itemId. Предмет с ещё
  не обработанным ответом не предлагается повторно; ошибочные offer очищаются по report.
- Станок считается свободным только при busyUntil=null. Равенство busyUntil текущему
  такту не разрешает запуск до подтверждённого освобождения в снимке.
- Для покупателя доступность тоже подтверждается cooldownUntil=null.
- Перед закупкой и запуском проверяется минимальное время оставшейся цепочки до
  робота. Длительности берутся из start. Завершение в последний такт допустимо.
- Ответы всех seq хранятся в RunStore до остановки сервера, без кэша на 16 событий.
- Память покупателей изолирована по runId. Стратегия не получает скрытый рынок
  симулятора и не использует раскрываемые buyers из finish.
- Используется существующий симулятор проекта с независимыми генераторами
  поставок и рынка; действия не меняют расписание будущих поставок.

## Структура

| Путь | Ответственность |
| --- | --- |
| `factory/server.py` | HTTP, JSON, токен, CORS, маршруты арены и панели |
| `factory/runs.py` | Прогоны по runId, блокировки, кэш seq, история и журнал |
| `factory/strategy.py` | Точка подключения основной стратегии |
| `factory/planning/controller.py` | Обработка событий, предложения в ожидании, производство в работе |
| `factory/planning/market.py` | Гипотезы о покупателях и связанные оценки цен |
| `factory/planning/policy.py` | Штатные веса, генерация и оценка действий, ограничения конца смены |
| `factory/planning/weights.py` | Чтение и сохранение весов в JSON |
| `factory/planning/schemas.py` | Внутреннее представление данных без сторонних библиотек |
| `factory/simulator.py`, `factory/config.py` | Собственная локальная модель v1 |
| `factory/demo.py` | Фоновая тестовая смена для панели |
| `scripts/` | Терминальный запуск, пакетная проверка миров и обучение весов |
| `web/` | Панель без сборки и JavaScript-библиотек |
| `tests/` | Проверки API, модели, повторов и найденных ошибок |

## API

- `GET /v1/health` → `{"status":"ok"}`.
- `GET /v1/info` → имя, версия, проект и версия спецификации.
- `POST /v1/runs/{runId}/start` → `{"ok":true}`.
- `POST /v1/runs/{runId}/event` → `{"commands":[...]}`.
- `POST /v1/runs/{runId}/finish` → `{"ok":true}`.
- `GET /api/runs` → список прогонов панели.
- `GET /api/runs/{runId}` → состояние, результат, история баланса и до 100 событий.
- `POST /api/demo` → локальная тестовая смена: `{"seed":1,"horizon":600,"delay":0.02}`;
  ответ `{"ok":true,"runId":"demo-..."}`. Это вспомогательный маршрут панели, не протокол арены.

Ошибки: `{"error":{"code":"...","message":"..."}}`. Поддерживается X-Arena-Spec=v1.
Если передан X-Arena-Seq, он должен совпадать с seq тела события.
Повтор start не сбрасывает знания; повтор seq возвращает сохранённый ответ.

## Подключение к арене

Для браузерной песочницы реализованы OPTIONS, CORS и Private Network Access.
Для зачётного раунда нужен публичный адрес/туннель и официальный check. Публичное
размещение в репозитории не настроено. Внешнее прослушивание:

```sh
python3 -m factory.server --host 0.0.0.0
```

Опционально задать ARENA_TOKEN. Все API-маршруты, включая health, данные панели
и запуск локальной смены, потребуют `Authorization: Bearer ...`. Тот же токен
указывается в кабинете арены и окне «Подключение» панели. В браузере токен не сохраняется.
Терминальный scripts.demo также читает ARENA_TOKEN.

## Ограничения

Состояние находится в памяти одного процесса. После перезапуска теряются знания,
журналы и история. Запуск нескольких процессов требует общего хранилища.
Снимок панели относится к моменту перед командами последнего события; итоговая
прибыль берётся из finish. JSON-экспорт содержит до 100 последних событий.

Симулятор собственный: одинаковые seed здесь и в официальной арене не означают
одинаковый мир. Его результаты не являются турнирной оценкой. Ограничения конца
смены учитывают минимальную цепочку операций, но не гарантируют отсутствие очередей
и доступного покупателя. Окончательная проверка — на официальном движке по openapi.yaml.
